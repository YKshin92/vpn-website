# 키 작업 기록 DB 적용·복원 검증

2026-10-18 · 개발 설명서 v0.19 · 로컬 DB 적용 완료

## 승인 및 범위

사용자가 2026-10-18에 로컬 DB 백업과 키 작업 기록 테이블 적용을 승인했다. 승인 범위에 따라 기존 파일/DB 상태를 확인하고 백업→006 적용→영속 기록·중복/동시 실행·복원·관리자 HTTP 검증을 수행했다. 실제 Outline 키 변경 스위치를 켜거나 실제 키를 생성·변경·삭제하지 않았다. AWS IP/DNS·GitHub 배포 변경도 없다.

## 적용 전 확인·백업

- 원본 DB: `ieum_vpn_dev`, localhost PostgreSQL 17.
- 기존 적용 001~005의 SHA-256 체크섬이 현재 소스와 일치했고, 유일한 대기 파일은 `006_outline_key_operations.sql`이었다.
- 기존 백업 포함 실행기 `tools/backend.ps1 -Task migrate` 사용. 백업 실패 시 마이그레이션은 진행하지 않는다.
- 변경 전 백업: `%LOCALAPPDATA%\IeumVPN\postgres-local\backups\before-migrate-20261018-001745-470.dump`, 43,723바이트.
- 변경 전 백업 SHA-256: `5ac7bbb0fb96781f5aab273f1bf366e20bde9b8c24b62629e24b43a9903f01a4`.
- `pg_restore --list`로 아카이브 구조 확인. 기존 적용 SQL은 수정하지 않았다.

006 적용 결과: `ieum_dev.outline_key_operations`, 작업 ID/서버·서버 세대·키 ID·작업자·요청 해시·상태/시각, 서버별 미완료 작업 하나를 강제하는 부분 고유 인덱스, 키 이력 조회 인덱스가 생성됐다. 앱 계정은 SELECT/INSERT/UPDATE만 부여받는다. 감사 기록 DELETE/DDL 권한은 부여하지 않았다.

## 실제 DB 영속 검증

무작위 `journal-test-*` 서버 식별자와 가상 키만 사용했으며 AWS/Outline 서비스 객체를 생성하거나 네트워크 호출하지 않았다.

- intent 기록이 새 저널 인스턴스에서도 조회됨.
- 같은 요청 ID/해시 완료 요청은 재실행 없이 기존 작업으로 판정.
- 같은 요청 ID에 다른 내용은 충돌로 거부.
- 동시 요청 2개 중 1개만 intent 생성, 다른 요청 차단.
- 생성 성공 시각 조회와 다른 서버 세대의 동일 키 ID 분리 확인.
- 중복 완료 기록 시도 거부.
- needs_review 기록 후 다른 요청은 새 저널 인스턴스에서도 차단.
- 앱 계정의 기록 DELETE와 CREATE TABLE 시도 거부. 권한 검사는 트랜잭션 롤백.

## 백업·별도 DB 복원

고유한 새 DB `ieum_vpn_key_restore_20261018_1792250344500`을 생성했다. 기존 복원 DB를 덮어쓰거나 삭제하지 않았다. 운영 API의 연결 DB도 바꾸지 않았다. 복원 DB는 PUBLIC 접속을 회수하고 앱 계정에만 접속 권한을 부여했다.

- 복원용 백업: `%LOCALAPPDATA%\IeumVPN\postgres-local\backups\outline-journal-2026-10-17T15-19-04-500Z.dump`, 47,216바이트. 파일명 시각은 UTC이며 한국 시각 2026-10-18 00:19이다.
- 백업 SHA-256: `b3cfd48586b8d59ef3bb01270388bf52967234fd19902e0102e444fc90c0b05f`.
- 익스포트한 읽기 전용 일관성 스냅샷으로 백업, 새 DB에 단일 트랜잭션 복원.
- 전체 `ieum_dev` 16개 테이블의 행/시각, 마이그레이션 6건, 제약 68개, 인덱스 35개, 앱 테이블 권한 항목 63개 비교.
- 원본·복원 비교 해시 일치: `44598b686901e119b4d0be29933426d721650fbcc6c8dd3e3af313e5bd428d1f`.
- 비교 시 가상 저널 3건을 포함했다. 단순히 빈 테이블 구조만 비교한 것이 아니다.
- 복원 DB에서 앱 계정으로 이력·생성일 조회, needs_review 후속 실행 차단, 부분 고유 인덱스 중복 거부, DELETE 제한을 재확인했다.
- 가상 기록은 원본과 복원 DB에서 정확한 시험 식별자만 지정해 관리자 계정으로 정리했다. 나머지 원본 데이터/구조의 전후 해시 동일 확인(`originalPreserved=true`). 백업에는 시험 당시 가상 3건이 들어 있다.
- 상세 보고서: `%LOCALAPPDATA%\IeumVPN\postgres-local\outline-journal-2026-10-17T15-19-04-500Z.json`.

전용 도구: `tools/verify-outline-journal.ps1` → `tools/verify-outline-journal.mjs`. 006 스키마 기준의 수동 로컬 검증 도구이며 재실행하면 한국 날짜를 포함한 새 복원 DB와 백업을 만든다. 삭제/덮어쓰기 기능은 없고 복원 DB는 검사 후 보관한다. 이 도구가 이후 관리자 작업의 자동 복구나 키 변경을 실행하지 않는다.

## 적용 후 회귀·실행 화면

- PostgreSQL 통합 테스트 50개 중 49개 통과, 1개는 기존 관리자 보존 사유로 생략. 시험 임시 관리자 등 정리.
- HTTP `/admin/keys`와 자산 200, 비로그인 키 API 401.
- 실제 서버 조회: 키 1개, 버전 1.12.3, 사용량/실험적 지표 정상.
- 현재 `journalReady=true`, `writesEnabled=false`. 실제 변경 요청은 403 `key-writes-disabled`로 거부되는 것 확인.
- 백엔드 재시작 없이 다음 읽기 조회에서 DB 준비 상태가 반영된다. 화면은 새로고침해 확인한다.
- 브라우저 클릭/시각 검증은 기존 접근 정책 제한으로 수행하지 않았다.

## 다음 승인 대상

이제 DB 적용 승인을 다시 받을 필요는 없다. 다음은 전용 테스트 키의 실제 생성→이름/한도 변경→조회 확인→삭제 시험이며, 실제 키 변경 승인과 쓰기 스위치 활성화가 별도로 필요하다. 결과 미확정 시 자동 재시도 없이 멈추고 영속 이력을 대조해야 한다. 기존 사용 키는 시험 대상으로 사용하지 않는다.
