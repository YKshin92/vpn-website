# 관리자 인증 및 신규 IP 유지 가상 관리

2026-10-16 / 작업 5 완료 / 로컬 가상 환경 전용

## 접속 및 최초 설정

관리자 주소: http://127.0.0.1:3000/admin

기존 4173 홈페이지 하단 ‘관리자 로그인’도 이 주소로 이동한다. 3000 백엔드는 프로젝트 폴더에서 다음 명령으로 시작한다.

```powershell
npm.cmd run build
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/backend.ps1 -Task start
```

처음 한 번 운영자가 브라우저에서 아이디·비밀번호를 직접 설정한다. 아이디는 영문·숫자·밑줄·하이픈 3~40자, 비밀번호는 8~128자다. 아이디는 소문자로 저장한다. 비밀번호는 문서·채팅에 전달할 필요가 없다. 실제 사용할 계정과 비밀번호를 개발자가 대신 정하지 않았다.

최초 등록은 DB 잠금과 기존 관리자 확인으로 한 계정만 생성한다. 관리자 존재 이후 등록 요청은 거부한다. 초기 등록은 신뢰하는 로컬 PC에서만 사용한다. 다른 로컬 사용자에 대한 초기 설정 접근 통제, 비밀번호 재설정·추가 관리자·역할 분리·MFA는 아직 구현하지 않았다.

테스트는 무작위 비밀번호의 가상 계정을 생성·검증·정리했다. 작업 완료 시 테스트 관리자·세션과 테스트 IP 작업 이력은 남기지 않았으며 사용자 최초 설정을 기다리는 화면을 확인했다.

## 인증과 접근 제한

- 비밀번호는 무작위 16바이트 salt와 scrypt(N=32768, r=8, p=1, 64바이트 결과)로 해시 저장한다. 로그인 시 timingSafeEqual로 비교한다.
- 로그인 시 세션 토큰을 새로 생성하고 DB에는 토큰 SHA-256만 저장한다. 만료는 8시간이다. 로그아웃하면 해당 세션을 삭제한다.
- 쿠키는 HttpOnly·SameSite=Strict·Path=/로 설정한다. 로컬 HTTP 전용이라 Secure는 사용하지 않는다. 외부 배포 시 HTTPS·Secure 및 전체 인증 정책 재검토가 필요하다.
- /api/dev/*, /api/admin/*와 로그아웃은 서버에서 세션을 검사한다. 비로그인은 401, 변경 요청의 CSRF 토큰 불일치는 403이다.
- 외부 Host·Origin·cross-site 요청을 거부한다. CSP·nosniff·no-store를 적용한다.
- 로그인·최초 등록 요청은 로컬 프로세스 기준 10분 동안 실패/시도 10회 이후 제한한다. 성공하면 카운터가 초기화된다. 재시작 시 제한 카운터도 초기화되므로 운영용 분산 제한을 대신하지 않는다.
- 관리 화면 HTML·CSS·JS 자체는 로그인 전에도 제공하지만 고객과 IP 상태·이력은 인증 API 없이는 조회할 수 없다. 클라이언트 화면 숨김만으로 권한을 구현하지 않았다.
- 기존 홈페이지의 고객용 가상 구매·내 이용권은 여전히 메모리 데모다. 관리자 고객 목록은 실제 로컬 DB를 조회한다. 이용기간·결제 조정 화면 연결은 후속 작업이다.

## 가상 IP 관리

기존 자동 원복 화면을 인증된 별도 관리 화면으로 교체했다. 외부 서비스 호출은 없으며 demo-server-01에 대한 문서 예시 IP와 .test 도메인만 사용한다.

기본 절차:

1. 신규 가상 IP 확보
2. 신규 IP 연결
3. 서비스 확인
4. DNS A 레코드 갱신
5. 접속 검증
6. 새 IP·DNS 유지 상태로 완료

정상 예: IP·DNS가 192.0.2.10에서 192.0.2.20으로 바뀌고 유지된다. 다음 성공 요청은 192.0.2.30으로 변경한다. 실제 IP 할당·서비스 점검·DNS 갱신·접속 검사가 수행되는 것은 아니다.

기존 IP 반환과 고객 키 변경은 하지 않는다. IP 연결 전 실패는 기존 IP를 유지하고 중단한다. 연결 이후 서비스·DNS·검증 실패는 현재 가상 상태를 그대로 저장하고 ‘관리자 확인 필요’로 중단한다. 자동 원복이나 추가 IP 할당을 반복하지 않는다.

확인 필요 상태에서는 신규 변경을 거절한다. 관리자가 표시된 현재 IP·DNS와 실패 단계를 확인하고 체크박스에 동의하면 ‘현재 신규 IP로 가상 완료’를 실행할 수 있다. 이 동작은 현재 가상 IP에 DNS를 맞춰 완료 처리하는 시뮬레이션이며 실제 장애 복구를 검증하지 않는다. 반환된 과거 IP를 재확보하는 가정은 없다.

DB 자문 잠금으로 동시 요청을 제한하고 revision 비교로 오래된 화면의 요청을 거절한다. 상태와 작업자·시각·단계 결과를 한 트랜잭션으로 저장한다. 새로고침·백엔드 재실행 이후에도 완료 결과와 최근 10개 이력을 조회할 수 있다.

실행 중 화면은 처리 안내를 표시하고 중복 버튼을 막는다. 서버는 완료 결과를 저장하므로 실시간 단계 스트리밍·실제 장시간 작업 큐·프로세스 종료 후 AWS 상태 재조정은 구현하지 않았다. 이는 향후 실제 인프라 작업 단계의 범위다.

## DB와 파일 변경

사전 pg_dump 백업 후 002_admin_and_simulation.sql을 적용했다.

- admins: 계정·salt·비밀번호 해시
- sessions: 토큰 해시·CSRF·만료·관리자 참조
- simulation_states: 서버별 가상 IP·DNS 상태와 revision
- simulation_jobs: 작업자·시각·가상 결과 이력

앱 계정에 위 테이블의 DML 권한을 추가했으며 DDL 권한은 없다. 초기 운영용 관리자 계정은 자동 삽입하지 않았다.

주요 소스: backend/auth.ts·simulation.ts·app.ts, dist/admin.html·css·js, dist/server-model.mjs, 기존 홈페이지 진입 버튼과 구 브라우저 전용 서버 대화상자 연결부. 기존 CLI IP 시뮬레이터는 과거 별도 검증 도구로 남아 있으며 현재 관리자 실행 경로에서 호출하지 않는다.

- 미인증 조회·IP 요청 차단, 잘못된 로그인, 세션 조회·만료·로그아웃·새 토큰 발급, CSRF 거부 확인.
- 동시 최초 등록에서 한 요청만 성공하고 이후 등록은 거부됨을 확인.
- 동시 IP 실행·오래된 revision 거절, 새 IP·DNS 유지, 부분 실패·명시적 완료와 DB 재조회 확인.
- 기존 복원 DB의 가상 데이터·앱 권한 유지와 미인증 API 차단 검사 1개 통과. 해당 DB는 이전 001 스키마의 역사적 복원본이며 002는 적용하지 않았다.
- 실제 HTTP 서버 두 차례 시작·종료 후 health 정상, 미인증 데이터 요청 401, 루프백만 바인딩 확인.
- 브라우저에서 최초 관리자 설정 화면 표시와 레이아웃 확인. 실제 사용자의 비밀번호는 입력·생성하지 않았으므로 사용자 계정으로 로그인한 뒤의 브라우저 조작은 미실행이다. 해당 기능은 무작위 테스트 계정의 API 통합 검사로 검증했다.

작업 4의 복원 시험은 001 스키마 기준이었다. 이번 인증 테이블·새 관리 데이터가 포함된 최신 백업의 실제 복원은 별도로 재검증해야 한다. AWS·DNS·Outline·실제 결제·중국 접속 검증과 GitHub 반영은 수행하지 않았다.

## 로컬 접속 장애와 복구 기록 — 2026-10-16

관리자 페이지에 연결되지 않아 확인한 결과, PostgreSQL 서비스와 관리자 백엔드가 모두 중지되어 있었다. 중지 원인은 확인되지 않았다. 기존 서비스를 시작한 뒤 tools/backend.ps1 -Task start를 별도 숨김 PowerShell 프로세스로 실행해 복구했다. 현재 출력 로그는 프로젝트의 local-admin.log·local-admin-error.log이며 버전 관리 대상에서 제외된다.

복구 후 /admin HTTP 200, health 정상 및 인증 상태 조회 성공을 확인했다. 실제 관리자 계정은 아직 설정되지 않아 최초 설정 화면 대상 상태다. 이번 브라우저 자동 확인은 도구의 URL 정책에 막혀 시각적 검증하지 못했다.

이 조치는 현재 실행을 복구한 것으로, 자동 시작을 설정한 것은 아니다. PostgreSQL은 수동 시작 설정이고 백엔드도 PC 재시작 후 다시 실행해야 한다. 소스·DB 스키마·관리자 계정·실제 인프라는 변경하지 않았다.

## 비밀번호 기준 변경 — 2026-10-16

사용자 요청에 따라 최초 설정·로그인의 최소 비밀번호 길이를 12자에서 8자로 변경했다. 최대 128자는 유지하며 화면 입력 제한·최초 설정 안내와 서버 검증을 함께 반영했다. 기존 계정의 비밀번호는 변경하지 않는다.

빌드·스크립트 문법 검사와 DB 통합 검사 18개가 통과했다. 정확히 8자 비밀번호의 계정 생성·로그인 성공 및 7자 요청 거부를 확인했다. 로컬 백엔드 재시작 후 실제 관리자 페이지 응답에도 minlength=8이 적용됐고 7자 로그인은 400으로 거부됐다. DB 스키마·실제 인프라·GitHub 변경은 없다.

## 다음 작업 제안

작업 6 후속 반영: 별도 ‘실제 서버 조회’ 메뉴와 읽기 전용 AWS·DNS API를 추가했다. 현재 AWS 인증 프로필이 없어 실제 조회는 대기 중이다. 최신 설정·검증·다음 절차는 [AWS·DNS 읽기 전용 연동](AWS_DNS_읽기전용_연동.md)을 따른다. 아래 내용은 작업 5 종료 시점의 제안이다.
