# 실제 IP 교체·기존 IP 반환 시험

2026-10-17 / 완료 / 기존 키로 사용자 연결 확인

후속 코드 개선: 이 시험의 수동 확인 구간을 보완하는 최대 2분 읽기 전용 DNS·서비스 대기를 구현·모의 검증했다. 이 실제 시험 자체는 개선 전 결과이므로 중간 개입이 없었던 것으로 바꾸지 않는다. [후속 구현](DNS전파_대기검증.md).

## 승인과 최종 상태

사용자는 ‘실제 IP 교체로 진행하자’로 실행을 요청했고, 본인 테스트만 사용 중이며 진행하라고 다시 확인했다. 새 IP·서비스·DNS 검증 후 기존 IP를 반환하는 정책을 적용했다. 이후 ‘기존 키로 정상 연결됨’을 직접 확인했다.

## 진행과 DNS 대기

실행 전 AWS 계정·기존 고정 IP 연결·공개/관리 DNS·현재 포트 정상을 확인하고 15분 유효 새 계획을 준비했다. 로컬 계획 저장 단계에는 실제 변경이 없었다. 사용자 승인 후 실제 시작 도구로 게이트를 활성화하고 같은 계획을 한 번 실행했다.

새 IP 할당·기존 IP 분리·새 IP 연결·TCP 서비스 확인·DNS 갱신은 성공했다. 공개 DNS 최종 확인 단계에서는 needs_review·pending=verify로 멈췄다. 이 시점에는 기존 IP를 반환하지 않았다.

이후 AWS 인스턴스·신구 고정 IP·관리 A 레코드·공개 DNS와 권한 DNS를 읽기 전용으로 대조해 새 주소가 반영됐음을 확인했다. DNS A 레코드 ID도 -2098318652로 바뀌었지만, 앞선 ID 교체 보완 코드 덕분에 DNS 갱신 완료 검사는 통과했다.

마지막 검증 실패가 DNS 전파 지연과 부합하는 상황이었으나, 실행기가 원본 오류 세부를 보관하지 않으므로 당시 실패 원인을 로그만으로 확정할 수는 없다. 실제 조회에서는 정상 전파가 확인됐다. 새 할당·연결·DNS 수정을 재실행하지 않았다.

## 같은 작업의 확인 후 속행

추가 실행을 막기 위해 로컬 관리자를 읽기 전용으로 복귀시켰다. 기존 사용자 실행 승인 범위에서 같은 작업의 잠금·계획 해시·정책·기존 승인 이벤트·완료 단계·새 IP를 확인하고, 반환 이벤트가 아직 하나도 없는지 검사했다.

확인 후 기존 어댑터의 verify와 release만 속행했다. 각 단계는 호출 전 intent와 완료를 DB에 기록했다. release에서는 구현된 계정·신규 연결·기존 미연결·DNS·TCP 조건을 다시 검증하고 ReleaseStaticIp 및 완료 확인을 수행했다. 이 단계는 별도 수동 ReleaseStaticIp 명령으로 대체하지 않고 새 자동 반환 어댑터를 사용했다.

최종 반환 intent는 1건이며, 반환 완료 후 oldIpCleanup.status=released와 반환 시각을 저장했다. 고정 IP 목록에는 새 IP 한 개만 남았다. 반환 호출을 다시 시도하거나 다른 IP를 추가 할당하지 않았다.

**한 번의 무인 실행으로 끝난 시험은 아니다.** 공개 DNS 확인에서 멈춘 뒤 운영자 상태 대조와 같은 작업의 속행이 필요했다. 새 반환 어댑터의 실제 성공은 확인했지만 DNS 대기부터 속행까지의 무인 흐름은 후속 개선 대상이다.

## 검증·영향·다음 작업

실제 HTTP에서 작업 succeeded·기존 IP 반환 기록·반환 intent 1건, 새 IP 상태 점검 정상, 익명 401·미등록 404·enabled=false를 확인했다. 검사 임시 관리자와 세션은 삭제했고 기존 관리자 계정·고객·키는 유지했다. 사용자 기존 키 재접속 확인까지 완료했다. 브라우저 시각 검사는 기존 도구 제한으로 미실행이다.

실제 AWS 변경: 새 고정 IP 할당·기존 IP 분리·새 IP 연결·ieumvpn.link A 갱신·기존 3.34.11.44 반환. IAM·Outline 설정·고객 키·결제·DB 스키마·GitHub 변경은 없다. 로컬 작업·감사 이력·문서만 추가 갱신했다. 이번 실제 시험 중 제품 코드는 변경하지 않았다.

다음 제안은 DNS 적용 완료와 공개 DNS 전파 대기를 구분하고, 정해진 시간 동안 읽기 전용 DNS·TCP 확인만 반복하는 기능이다. AWS 할당·연결·DNS 수정·반환을 자동 재전송하는 기능과 구분해야 한다. 시간 초과·인증/권한 오류·실제 주소 불일치 시에는 계속 확인 대기로 멈추도록 설계한 뒤 사용자 승인 후 구현한다.
