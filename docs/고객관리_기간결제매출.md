### 고객 상세 우측 플로팅 패널

2026-10-17 사용자 요청으로 고객 표의 ‘상세·이력’을 누르면 화면 오른쪽의 modal 패널이 열리도록 변경했다. 기존 기간 수정·메모·결제/환불·감사 이력 기능과 API를 유지한다. 배경 클릭·Esc·닫기 버튼으로 닫으며, 닫은 이후 늦게 도착한 조회 응답이 다시 패널을 열지 않도록 조회 번호를 무효화한다. native dialog로 배경 포커스를 제한하고 닫을 때 원래 버튼으로 포커스가 복귀하도록 한다.

패널 내부에서 독립 스크롤하고 제목·닫기 버튼은 상단에 고정한다. 좁은 화면은 전체 너비를 사용하며, 동작 줄이기 설정에서는 등장 애니메이션을 끈다. 저장 결과·오류 메시지도 패널 안에 표시한다. Noto Sans KR은 유지한다.

변경 파일: dist/admin.html·admin.js·admin.css. 기존 기본 테스트 43개 통과·UI 컨트롤러 검사 4개 재확인·JS 문법·HTML 구조 확인. 실제 HTTP에서 새 dialog·닫기 코드·CSS 제공 200 확인. 브라우저 시각 검사는 기존 도구 정책 제한으로 수행하지 않았다. DB·AWS·키·결제·GitHub 변경이나 관리자 재시작은 없다. 다음은 사용자 화면 검토 후 폭·정보 배치를 조정하는 것이다.

## 화면 구성과 범위

상위 메뉴는 고객관리와 서버관리 두 개다. 고객관리에서 현황·검색·기간·과거 결제·환불·운영 메모·매출을 관리한다. 서버관리에는 실제 서버 조회·변경 승인 계획을 먼저 배치하고 모의 작업·간단 시험은 접어서 확인하도록 정리했다.

이번 장부는 .test 이메일 가상 고객 전용이다. 수납·환불 기록 추가는 실제 결제·계좌이체·환불을 실행하지 않는다. 기간·상태 수정도 실제 Outline 키 발급·회수·연장과 연결되지 않았다. 기존 홈페이지의 가상 구매 데이터와 별도이며 PG 연동 매출로 간주하지 않는다.

## 고객 현황과 보완 기능

- 표시: 고객명·이메일·상태·개별 키 ID·서버 ID·요금제·시작·만료 시각·남은 기간.
- 요금제: 무료 1일 체험·30일·90일·180일. 체험은 수납 입력 대상에서 제외한다.
- 남은 기간: 만료 시각까지의 남은 초를 24시간으로 나누어 올림. 이미 만료되면 0일, 날짜 미설정이면 미설정이다.
- 상태: 관리자 확인 필요·결제 대기·수동 만료 상태를 우선하고, 나머지는 실제 시작·만료 시각에 따라 이용 중·시작 예정·만료·기간 미설정을 표시한다. DB 관리 상태와 계산된 표시 상태를 구분한다.
- 고객명·이메일·키 ID 검색, 이용 중·7일 내 만료·만료·대기·확인 필요·시작 예정·미설정 필터, 페이지당 50명.
- 전체 고객·이용 중·7일 내 만료·결제 대기 요약은 전체 고객 기준이며, 검색 결과 건수는 별도로 표시한다.
- 기간·상태·운영 메모 수정 시 revision 비교로 오래된 화면의 덮어쓰기를 차단하고 작업자·수정 전후를 기록한다. 시작·만료는 함께 설정하거나 함께 비우며, 만료는 시작보다 늦어야 한다.
- 모든 화면 날짜와 날짜 입력은 한국 시간 기준이다. 저장은 timezone 포함 timestamptz로 한다.

## 과거 결제와 수동 장부

고객 선택 시 해당 고객 ID 또는 현재 이메일과 일치하는 결제 당시 이메일로 과거 장부를 조회한다. 결제 당시 이메일을 별도로 보존하므로 고객 이메일이 이후 바뀌어도 해당 고객 ID의 과거 이력은 유지된다. 키는 이메일 기준으로 공유하지 않고 기존 고객별 연결을 유지한다.

결제 이력은 최근 200건이며 결제일·당시 이메일·요금제·상태·금액·환불액·메모를 표시한다. 환불 이력도 최근 200건, 고객 작업 이력은 최근 30건이다. 더 오래된 대량 이력의 페이지 탐색·CSV 내보내기는 후속 범위다.

수납 기록은 완료·대기·실패·취소 상태, 요금제, 원화 정수 금액, 메모, 완료된 경우 결제 시각을 받는다. 동일 요청 번호의 중복 저장을 막고 다른 내용으로 번호를 재사용하면 거부한다. 수납 기록만으로 이용기간을 자동 변경하지 않는다.

환불은 완료 결제에 대해서만 기록한다. 결제일보다 빠른 환불 시각·남은 금액 초과를 거부한다. 결제 행 잠금 안에서 기존 환불 합계를 확인하므로 동시 요청도 한도를 넘지 않는다. 같은 환불 요청 번호는 한 번만 기록한다. 환불 사유와 작업자를 남긴다. 원 수납 기록을 덮어쓰지 않는다.

## 일별·월별 매출 기준

- 원화 KRW, 한국 시간 Asia/Seoul 기준의 시작·종료일과 일별/월별 선택.
- 기간의 시작일 00:00 이상, 종료일 다음 날 00:00 미만으로 조회한다.
- 완료 결제는 paid_at 기준 결제액·건수에 포함한다. 대기·실패·취소는 제외한다.
- 환불은 원 결제 월을 소급 수정하지 않고 refunded_at 기준 환불액에 반영한다.
- 순매출 = 결제액 − 환불액. PG 수수료·세금·환율을 반영한 순이익이 아니다.
- 거래 없는 날·월도 0으로 표시하고 환불만 있는 기간은 순매출이 음수일 수 있다.
- 합계 카드·기간별 표·결제액 비교 막대를 제공한다. 조회 범위는 최대 367일이다.
