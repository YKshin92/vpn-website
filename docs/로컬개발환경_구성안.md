# 로컬 개발 환경 확인 및 구성안

작성일: 2026-10-16 / 작업 1 완료 / 설치·구현 승인 대기

> 후속 업데이트: 작업 2가 별도 승인되어 PostgreSQL 17.11 설치·개발 DB·앱 계정·접속·재시작 검증을 완료했다. 아래 미설치 표는 작업 1 시점의 기록이다. 현재 적용 값은 [로컬 DB 설치 및 운영 기록](로컬DB_설치및운영.md)을 따른다. 백엔드 구축은 아직 미실행이다.

## 1. 확인 범위와 결과

사용자가 승인한 읽기 전용 환경 확인 결과다. 설치·실행 설정 변경·DB 생성·스키마 변경은 하지 않았다.

| 항목 | 관찰 결과 | 판단 |
| --- | --- | --- |
| Node.js | v24.18.0 실행 확인 | 기존 런타임 활용 후보 |
| npm | 11.16.0 실행 확인 | 패키지 관리 가능; 실제 패키지 설치는 미실행 |
| PostgreSQL 명령 | psql·postgres·pg_dump·pg_restore를 PATH에서 찾지 못함 | DB·백업 도구 설치 필요 후보 |
| PostgreSQL 설치 | 기본 Program Files 경로 없음, 관련 설치 레지스트리·서비스 조회에서 발견 안 됨 | 확인 범위에서 미발견; 모든 디스크 검색 결과는 아님 |
| Docker·Podman | PATH 및 확인한 Docker 기본 경로·관련 서비스에서 미발견 | 현재 사용할 수 있는 컨테이너 환경 확인 안 됨 |
| WSL | wsl.exe는 있으나 상태 조회 실패, 설치 안내 출력 | 정상 사용 가능한 환경으로 간주하지 않음 |
| 포트 | TCP 리스닝 목록에서 5432·5433·3000·4173 없음 | 확인 시점에 사용 중이지 않음; 실행 직전 재확인 |
| C 드라이브 | 약 737GB 여유 | 확인 시점 기준 |
| 프로젝트 | dist·fixtures·tests·tools·docs 및 preview.cjs | 기존 정적 홈페이지 구조 유지 가능 |
| 백엔드·DB 정의 | 검색 범위에 package.json·잠금 파일·Compose·SQL·마이그레이션 파일 없음 | 백엔드와 스키마 신규 구축 필요 |
| 미리보기 | preview.cjs는 127.0.0.1:4173의 dist 정적 파일 제공 코드 | DB API가 없는 개발용 서버 |

일반 권한에서 서비스·포트 조회가 제한되어 읽기 전용 권한 확장으로 재확인했다. 프로그램 설치나 서비스 시작·정지는 수행하지 않았다. 실제 비밀번호·환경변수 값·고객 정보는 조회하지 않았다.

## 2. 권장 구성 — 승인 전 제안

Windows에 PostgreSQL을 직접 설치하고, 기존 Node.js로 백엔드를 개발한다. Docker·WSL 설치는 이번 구성에서 제외하는 방안을 제안한다. PostgreSQL 공식 Windows 안내에서 연결하는 설치 프로그램을 사용한다. 설치 버전·필수 구성요소·다운로드 출처는 설치 직전 확인하고 기록한다.

근거: [PostgreSQL 공식 Windows 설치 안내](https://www.postgresql.org/download/windows/)에는 EDB 설치 프로그램과 고급 사용자용 바이너리 배포가 안내되어 있다. 기존 환경에는 사용할 수 있는 Docker가 확인되지 않아 직접 설치를 우선 제안한다.

| 구성 | 제안 |
| --- | --- |
| 프런트엔드 | 기존 HTML·CSS·JavaScript 유지 |
| 백엔드 | Node.js·TypeScript; 프레임워크·드라이버 버전은 후속 백엔드 계획에서 확정 |
| DB | PostgreSQL; 로컬·서버에서 같은 메이저 버전 사용을 우선 검토 |
| DB 접속 | 127.0.0.1:5432, 외부 네트워크 공개 없음 |
| DB명 | ieum_vpn_dev, 복원 시험은 ieum_vpn_restore_test |
| DB 권한 | 초기 관리용과 애플리케이션용 계정 분리, 앱에 관리자 권한 부여하지 않음 |
| 데이터 경로 | 프로젝트 밖의 로컬 전용 경로; 기본 설치 경로 제안 후 승인 시 확정 |
| DB 인증 | 비밀번호 인증; 비밀번호는 문서·명령 출력·저장소에 기록하지 않음 |
| 프런트/API 연결 | 로컬 개발 시 동일 출처로 제공하는 방향; 실제 포트·구현은 백엔드 계획에서 확정 |
| 마이그레이션 | 버전별 SQL 파일과 적용 이력; 실행 대상 DB 확인 후 승인 범위에서 적용 |
| 설정 | 비밀 값 없는 .env.example, 실제 로컬 설정은 버전 관리 제외 |
| 백업 | pg_dump·pg_restore 사용 계획, 프로젝트 밖의 제한된 로컬 경로에 보관 |

설치 프로그램이 Windows 서비스 등록·관리자 권한을 요구할 수 있다. 실제 설치 전에 변경될 경로·서비스·포트·자동 시작 여부를 설명하고 승인받는다. 추가 구성요소와 자동 시작 여부는 기본 선택을 무조건 수용하지 않고 제안 범위를 따른다.

DB 데이터 디렉터리를 다른 운영체제 서버에 그대로 복사하는 방식은 이전 계획으로 사용하지 않는다. 백업·복원과 환경별 연결 설정으로 이전하고 버전·확장 호환성을 검증한다. 운영 인증·키 저장과 실제 결제는 이 구성 단계에 포함하지 않는다.

## 3. 다음 작업 2 제안 범위

사용자의 별도 최종 승인 후 실행한다.

1. 공식 배포 경로에서 PostgreSQL 설치 대상 버전과 구성요소를 확정해 설명
2. 서버와 CLI·백업 도구를 로컬에 설치하고 실행 환경 기록
3. 로컬 전용 접속·포트·데이터 경로와 비밀번호 인증 구성
4. 개발 DB와 제한된 앱 계정 생성 — 설치 승인에 DB·계정 생성 범위도 명시
5. 가벼운 연결 검사와 DB 재시작 후 연결 확인; 실제 고객 테이블·데이터는 생성하지 않음
6. 결과·설정의 비밀이 아닌 항목·중단/삭제 시 데이터 보존 방법을 작업 현황에 기록

설치 중 다른 권한·재부팅·예상하지 않은 구성 변경이 필요하면 범위를 설명하고 추가 승인 후 진행한다. 서비스 재시작 검사도 새 개발 DB에 한정하고 기존 서비스를 건드리지 않는다.

## 5. 이번에 실행하지 않은 항목

소프트웨어 다운로드·설치, 패키지 설치, DB 생성·마이그레이션, 서비스 시작·정지, 방화벽 변경, AWS·DNS·Outline 호출, GitHub 커밋·푸시·배포는 수행하지 않았다. 프로그램 코드를 변경하지 않아 기능 테스트도 재실행하지 않았다.
