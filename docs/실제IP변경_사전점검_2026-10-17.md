## 후속 확인 — 재설치와 포트 변경

사용자는 서버 접속 문제로 재부팅 후 Outline을 재설치했고 포트가 바뀌었다고 확인했다. 현재 정상 연결은 휴대폰 모바일 데이터에서 `ieumvpn.link:54137`을 사용하는 경우다. Windows TCP 점검도 `3.35.1.102:54137`에 연결됐으며 공개 A는 여전히 `3.35.1.102`다. 이전 40665 점검 실패를 현재 서비스 장애나 PC 네트워크 문제의 증거로 사용하지 않는다.

기존 저장 계획의 40665는 현재 서비스와 다르므로 실행 대상으로 사용하지 않는다. 아직 실행 중 백엔드 설정·저장 계획을 변경하지 않았고 실제 변경 게이트도 활성화하지 않았다. 다음 제안 범위는 서비스 확인 포트를 명시적으로 54137로 설정하고 읽기 전용 백엔드를 재시작한 뒤 기존 미실행 계획을 종료하고 최신 조회로 새 계획을 생성하는 것이다. 이 로컬 변경 범위를 설명하고 승인받은 후 진행한다. 실제 IP·DNS 변경은 별도 최종 승인 대상이다.

재설치 전 키·Management API 주소·인증서 정보가 보존됐는지는 미확인이다. 현재 정상 키가 있다는 사실만으로 기존 고객 키 전체가 유지됐다고 판단하지 않는다. 관리 API 비밀정보나 전체 키를 채팅에 요청하지 않는다. 아래 점검·계획 표는 포트 변경 확인 이전의 이력이다.

## 승인·이용 현황

사용자는 ‘실제 변경 없이 실행 전 점검과 새 계획 작성’ 제안에 ‘진행해줘’로 승인했다. 이후 다른 이용자 없이 본인 테스트만 사용 중이며 현재 Outline 앱은 정상 연결된다고 답변했다. 이는 실제 리소스 변경 승인이 아니다.

## 예상 비용

AWS 공식 문서는 인스턴스에 연결된 고정 IP 자체에 별도 비용이 없고, 미연결 상태가 1시간을 넘으면 시간당 US$0.005라고 안내한다. 따라서 교체 후 기존 IP를 계속 보관하면 이 비용이 발생할 수 있다. 장기 보관의 24시간 단순 환산은 US$0.12이며 세금·실제 과금 시간은 별도다. 이번에는 새 IP를 할당하지 않았으므로 이 시험의 미연결 IP 비용을 새로 발생시키지 않았다.

## 사전 차단 보완

기존 실행기는 새 IP 연결 이후에 TCP 서비스를 확인했다. 점검 PC의 기존 서비스 경로가 이미 실패하는 경우, 그 경로로 새 IP 검사도 성공한다고 볼 수 없다. 실제 어댑터의 preflight 끝에 현재 IP·서비스 포트의 TCP 확인을 추가해 실패하면 AllocateStaticIp 호출 전에 중단하도록 했다. 기존 자동 재시도·원복 금지 원칙은 유지한다.

빌드와 기본 테스트 38개 통과. DB 통합은 42개 중 41개 통과·기존 관리자 보존을 위한 1개 생략이다. 가짜 preflight가 실패할 때 호출 목록에 preflight만 있고 allocate·detach는 없음을 검증했다. 실제 어댑터 생성·쓰기·서비스 변경을 시험한 것은 아니다. 실제 실행 시작 도구는 실행하지 않았다. 실행 중 백엔드는 기존 코드와 실제 변경 비활성 설정을 유지한다. 추가한 사전 검사는 다음 백엔드 재시작 시 적용된다.

## 다음 단계와 중단 시 대응

1. 현재 정상 연결 앱이 이 PC인지 휴대폰인지, 같은 Wi-Fi인지 모바일 데이터인지 확인한다.
2. 전체 키 대신 현재 정상 키의 도메인:포트만 대조한다. 키·비밀번호·관리 API 비밀 URL은 받지 않는다.
3. 점검 경로 또는 포트를 확인해 기존 TCP 점검이 정상 통과하는지 확인한다. 네트워크·서버 설정 변경이 필요하면 범위를 설명하고 승인 후 수행한다.
4. 계획 만료 시 새로 조회하고, 서비스 중단·비용·기존 IP 보유·실패 대응을 보여준 뒤 실제 실행을 별도 승인받는다.
5. 실행 중 불명확한 오류가 생기면 현재 AWS 연결·DNS·단계를 보존해 needs_review로 멈춘다. 추가 할당·자동 원복·기존 IP 반환 없이 수동 확인한다. 복구 변경은 실제 보유 상태와 서비스 확인 후 별도로 결정한다.

실제 IP·DNS·IAM·Outline·키·GitHub 변경 없음. 로컬 계획의 취소·갱신과 코드의 사전 차단만 반영했다.
