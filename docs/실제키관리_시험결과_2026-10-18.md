# 실제 Outline 키 관리 시험 결과

2026-10-18 · 개발 설명서 v0.20 · 승인된 전용 키 시험 완료

## 승인·실행 범위

사용자가 전용 테스트 키 1개의 생성→이름/한도 변경→삭제 시험을 승인했다. 대상은 서울 vpnServer001·ieumvpn.link·Outline 1.12.3이다. 한국 시각 2026-10-18 00:24:13~00:24:29에 실행했다.

실행 중인 브라우저용 관리자 서버는 계속 읽기 전용이었다. 별도 포트를 열지 않는 일회성 Fastify inject 프로세스에서 동일 관리자 세션·CSRF·스키마·제어 서비스·DB 저널 경로를 사용하고, 승인된 시험 대상에만 실제 키 변경을 허용했다. IP 변경 스위치는 false 유지, 서버 공개 주소·DNS 수정·기존 키 변경은 수행하지 않았다.

기존 키 전체의 ID·이름·포트·개별/기본 한도 정보를 시험 전후 비교했고 동일했다. 서버 식별자·키 호스트·기본 포트·기본 한도·공개 IP·도메인도 동일했다. 변경 작업 5개가 모두 DB succeeded로 남는 것을 확인했다. 실패·자동 재시도·잔여 테스트 키는 없다. 시험 임시 관리자와 세션은 정리했으며 감사 이력의 작업자 문자열과 결과는 보존했다.

## 종료 상태·한계

- 실제 관리자 HTTP에서 최종 키 1개·버전 1.12.3·사용량/실험적 지표 정상 재확인.
- `journalReady=true`, `writesEnabled=false`. 비로그인 조회 401, 실제 변경 요청 차단 403 재확인.
- 별도 브라우저 쓰기 활성화나 운영 서버 재시작은 하지 않았다.
- 고객 매핑·결제·요금제/기기 제한·사용량 소진 시 실제 차단·Outline Client의 신규 키 접속은 이번 시험 범위가 아니다.
- 기존 브라우저 정책으로 클릭/시각 검증은 미실행이다. 동일 API 핸들러에 대한 실제 Outline·DB 통합 시험으로 구분한다.
- GitHub 커밋·푸시·배포는 하지 않았다.

## 실행 자료

`tools/test-outline-live-key.ps1 -ApprovedLiveKeyTest`와 `tools/test-outline-live-key.mjs --approved-live-key-test`를 작성했다. 재실행은 별도 승인이 필요하다. `.build/outline-live-key-test-state.json`이 있으면 추가 키 생성 전에 중단하도록 했으며 자동 재시도하지 않는다. 실제 시험의 관리 비밀은 기존 암호화 저장소에서 서버 측으로만 읽는다.

상태 파일에는 기준 키의 안전한 메타데이터와 해시·작업 ID·시험 키 ID·단계별 결과만 저장한다. 관리 URL·인증서·키 비밀번호·전체 접속 URL은 포함하지 않는다. 실제 단계별 감사 이력은 로컬 PostgreSQL에 보존된다.
