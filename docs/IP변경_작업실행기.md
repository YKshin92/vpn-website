# IP 변경 작업 실행기와 여러 서버 조회

2026-10-17 / 작업 7: 영속 모의 실행기·비활성 Lightsail 변경 어댑터 코드 구현

후속 반영: 실제 승인 전용 테이블·HTTP 실행 경로를 연결하되 서버 측 게이트는 비활성으로 유지했다. 관리자 상위 탭도 고객관리/서버관리 두 개로 재정리했다. 최신 승인·실행 경계는 [실제 IP 변경 승인 계획](실제IP변경_승인계획.md)을 따른다. 아래의 실제 경로 미연결 문구는 작업 7 완료 당시 기록이다.

## 승인 범위와 실행 경계

사용자는 작업 계획·단계 저장, 중복 실행 방지, 실패·중단 처리, 모의 AWS 검증 및 사전 백업 후 로컬 DB 테이블 추가를 승인했다. 이어 실제 서버 조회 화면을 여러 서버 운영 기준으로 조정하도록 요청했다.

실제 AWS IP 할당·분리·연결·반환·DNS 갱신은 실행하지 않았다. 실제 조회는 계속 읽기 전용이다. HTTP 작업 API와 DB 작업 테이블은 mock 모드만 허용한다. 실제 SDK 변경 어댑터는 app.ts·HTTP 경로에서 가져오지 않으며 기본 비활성이다. 실제 실행 진입점·live 작업 DB 허용·운영 승인 연결은 아직 없고, 다음 작업에서 범위와 계획을 승인받아야 한다. 따라서 이번 완료는 실제 운영 변경 기능이 활성화됐다는 의미가 아니다.

## 모의 작업 사용

관리자 화면에서 ‘변경 작업 검증’을 선택한다.

1. 정상 또는 실패 단계를 선택하고 ‘모의 변경 계획 만들기’를 누른다.
2. 대상 mock-vpnServer001, .test 도메인, 문서용 변경 전 IP·DNS와 신규 IP 이름을 확인한다.
3. 체크박스를 선택하고 ‘계획대로 모의 실행’을 누른다.
4. 정상 완료 시 모의 IP·DNS는 192.0.2.20을 유지한다. 기존 IP 반환·고객 키 변경은 없다.
5. 실패 시 마지막으로 확인된 상태·실행 예정 단계와 불확실성 표시를 남기고 확인 대기로 멈춘다.
6. 상황을 확인하고 10자 이상 메모로 ‘확인 종료’할 수 있다. 확인 종료는 성공이나 복구가 아니며, 보관한 상태를 바꾸지 않고 다음 모의 계획을 허용한다.

이 모의 실행기는 기존 ‘가상 IP 시험’과 독립이다. 각 계획은 문서용 192.0.2.10에서 시작하는 독립 시나리오이며 실제 서버 목록의 대상·IP를 변경 계획으로 자동 변환하지 않는다.

## 저장과 장애 처리

- rotation_jobs: 요청 번호, 대상, 모드, 작업자, 계획, 마지막 확인 상태, 실패 단계, 상태·revision, 생성·수정 시각.
- rotation_events: 계획 저장·단계 실행 예정·완료·실패·중단·관리자 확인 기록. 각 기록의 revision은 작업과 같은 트랜잭션으로 저장한다.
- 단계: allocate → detach → attach → service → dns → verify.
- 작업 상태: planned → running → succeeded, 실패·중단 시 needs_review, 확인 종료 시 closed.
- 공급자 호출 전 intent를 커밋한다. 저장이 실패하면 호출하지 않는다. 호출 후 완료 저장에 실패하면 다음 단계로 진행하지 않는다.
- 공급자 오류는 효과가 전혀 없었다고 단정하지 않는다. 자동 재시도·원복·추가 할당·기존 IP 반환 없이 확인을 요구한다.
- PostgreSQL 세션 자문 잠금으로 실행과 복구를 직렬화한다. 열려 있는 대상 작업의 부분 고유 인덱스도 중복 계획을 막는다. 현재 실행 대상은 한 개의 고정 모의 서버다.
- 같은 요청 번호·작업자·내용은 저장된 계획을 반환한다. 다른 내용의 재사용, 오래된 revision, 성공 작업 재실행을 거부한다.
- 시작 시 또는 관리자 ‘중단 상태 확인’ 요청 시 running 작업이 있고 실행 잠금이 비어 있으면 중단으로 판단해 needs_review로 전환한다. 새 실행 프로세스가 기존 단계의 외부 효과를 재전송하지 않는다. 다른 프로세스가 실제로 잠금을 보유 중이면 해당 작업을 건드리지 않는다.
- 실행 중 응답은 최종 결과 반환 방식이며 실시간 단계 스트리밍은 없다. 최신 작업 목록 30개·선택한 작업의 전체 단계를 조회한다.
- 이전 복원 DB에 새 테이블이 없으면 시작 복구를 건너뛴다. 새 작업 기능은 최신 마이그레이션이 있는 개발 DB에서 사용한다.

## 실제 Lightsail 어댑터 코드

backend/lightsail-rotation-driver.ts는 실제 실행 승인을 명시적으로 전달하지 않으면 AWS 클라이언트 생성 전 거부한다. 현재 서비스에서는 이 생성 함수를 호출하지 않는다. 테스트는 주입한 가짜 연산만 사용했다.

코드상 준비된 절차는 계정·인스턴스·기존 고정 IP·DNS 레코드 ID·A 값·NS를 재확인한 뒤 신규 고정 IP 할당, AWS 작업 완료 및 IP 조회, 기존 IP 분리, 신규 IP 연결과 실제 연결 확인, TCP 서비스 확인, 승인된 Lightsail A 레코드 갱신, DNS·TCP 재검증이다. AWS 자동 재시도 횟수는 1이며 작업 상태 조회는 횟수 제한을 둔다. API 오류·시간 초과는 상위 실행기에서 확인 대기로 처리해야 한다.

기존 IP 반환·Outline 키·관리 API 호출은 구현하지 않는다. TCP 성공은 Outline 인증·데이터 전송 성공을 뜻하지 않으며 동일 키의 실제 클라이언트 검증이 필요하다. DNS 전파 대기는 추가 할당·원복 근거가 아니다. 실제 SDK 변경 응답·IAM 쓰기 권한·운영 중 장애 복구는 이번에 검증하지 않았다. 운영 실행 전 어댑터와 영속 journal의 live 경로, 대상별 잠금·승인·상태 대조를 연결하고 별도 검증해야 한다.

## 여러 서버 조회 설계

‘실제 서버 조회’는 등록 수·실행 중·확인 필요 요약, 서버 카드 목록, 선택한 서버 상세로 구성했다. 카드에 인스턴스명·리전·상태·공인 IP·도메인·DNS 일치 상태를 보여준다. 각 서버의 오류와 도메인을 독립적으로 표시한다. 실제로 확인되지 않은 가상 서버 카드는 넣지 않았다.

IEUM_AWS_SERVER_TARGETS 환경 변수의 서버 측 JSON 배열로 최대 10대의 서울 서버를 등록할 수 있다. 각 항목은 instance·domain이다. 중복 인스턴스명·유효하지 않은 도메인·빈 배열·10대 초과를 거부한다. 생략하면 기존 vpnServer001·ieumvpn.link 한 대를 조회한다. 여러 AWS 계정·여러 리전 및 화면에서 서버 추가·삭제하는 기능은 아직 없다.

```json
[{"instance":"vpnServer001","domain":"ieumvpn.link"}]
```

추가 서버는 실제 이름·도메인을 확인한 후 배열에 추가하고 백엔드를 다시 실행한다. 예시 서버를 실제 설정에 임의 추가하지 않았다. 목록 API는 servers 배열과 전체 fleetStatus를 추가했고 기존 단일 서버 응답 필드도 유지한다.

## DB 변경·검증·적용

- 사전 백업: 보호된 로컬 backups 폴더의 before-migrate-20261017-150714-798.dump, 16,731바이트. 이 백업은 003 적용 전 상태다.
- 003_rotation_jobs.sql 적용: 두 테이블·작업 중복 인덱스·앱 DML 권한. 기존 고객·키·관리자 및 기존 스키마는 유지했다. 이번 새 테이블을 포함한 백업 복원은 별도 미검증이다.
- 빌드·JS 문법 검사 및 기본 테스트 36개 통과.
- DB 통합 Node 집계 27개 중 26개 통과·기존 관리자 보존을 위한 최초 설정 1개 생략. 검사 계정·작업·이력은 제거했다.
- 중복 계획·요청 재사용·동시 실행·오래된 revision·실패 후 재할당 차단·불완전 상태의 새 앱 시작 복구·실행 잠금 중 복구 건너뜀을 확인했다. 프로세스를 강제 종료한 외부 효과 시험 대신 DB의 중단 상태를 재현해 검증했다.
- 실제 HTTP: /admin 200·새 메뉴, 비로그인 작업 API 401, 임시 관리자 모의 계획 생성·실행 성공·이력 13개 저장 확인. 실제 조회 servers 1대·IP 3.35.1.102·공개 DNS 일치 확인.
- 로컬 백엔드를 재시작해 적용했다. 브라우저 도구의 기존 URL 정책 제한으로 시각 검증은 미실행이며 사용자 새로고침 확인이 필요하다.
- 실제 IP·DNS·IAM·Outline 변경 및 GitHub 커밋·푸시·배포 없음.
