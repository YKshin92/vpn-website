## 최신 상태

최신 실제 시험: a4bbd410-db90-4481-a050-a072e022843e / 3.34.11.44에서 52.79.185.31로 변경·기존 IP 반환·사용자 기존 키 정상 연결 확인. DNS 확인 대기 후 같은 작업의 검증·반환만 속행했으며 추가 할당/중복 DNS 수정은 없다. [실제 결과와 남은 대기 처리](실제IP변경_자동반환시험_2026-10-17.md). 관리자 enabled=false.

정책 업데이트: 신규 계획은 검증 후 기존 IP 자동 반환(policyVersion=2)으로 변경했다. 이전 보관 계획은 그대로 보존하되 실행할 수 없으며 미실행 계획은 취소·재생성이 필요하다. 새 반환 확인 항목과 마지막 단계·불확실 응답 중단을 구현·모의 검증했다. 실제 실행은 비활성이고 이번에 실제 IP 변경은 없다. [현재 반환 정책·검증](IP교체_기존IP자동반환.md). 아래 보관 정책은 과거 이력이다.

**실제 시험 완료:** 사용자 실행 승인과 기존 IP 반환 추가 승인 후 vpnServer001의 IP를 3.34.11.44로 변경하고 ieumvpn.link A를 갱신했다. 기존 3.35.1.102 반환·사용자 앱 정상 연결 확인. 작업 d5d850ba-f029-4d9a-9484-383a4c9eee82 최종 succeeded, 실제 실행 게이트 false. DNS ID 교체에 따른 확인 대기와 수동 대조·보완 내역은 [시험 결과](실제IP변경_시험결과_2026-10-17.md)를 따른다. 아래 미실행·이전 IP·계획 문구는 당시 이력이다.

최신 로컬 준비 완료: 사용자의 ‘웅웅’ 승인으로 읽기 전용 관리자를 ServicePort=54137로 재시작하고 계획 560290f7-ed40-4099-bdac-36e1ded4f17f를 저장했다. 이전 미실행 계획은 실행 잠금·무효과 확인 후 종료했다. Node/Windows TCP 성공, HTTP에서 새 포트·planned·enabled=false 확인. 새 계획 최초 만료 2026-10-17 22:17:40 KST이며, 실제 실행 승인이나 IP·DNS 변경은 아직 없다. 아래 이전 계획·보류 문장은 이력이며 최신 상세는 사전 점검 기록 상단을 따른다.

후속 확인: 사용자가 Outline 재설치로 포트가 변경됐음을 알렸다. 휴대폰 모바일 데이터에서 현재 키 `ieumvpn.link:54137` 정상, 점검 PC의 Windows TCP도 새 포트 연결 성공이다. 기존 40665 기반 계획은 사용하지 않는다. 서비스 포트 설정·읽기 전용 재시작·미실행 계획 갱신은 다음 승인 범위로 제안하며 아직 수행하지 않았다. 실제 IP·DNS 변경 게이트는 비활성이다. 재설치 전 고객 키·관리 API 정보의 유효성은 미확인이다.

최신 사전 점검은 [2026-10-17 점검 기록](실제IP변경_사전점검_2026-10-17.md)을 따른다. 다른 이용자는 없고 본인 Outline 앱은 정상 연결되지만, 자동화 PC의 기존 서비스 TCP 점검이 시간 초과되어 실제 변경은 보류했다. 기존 계획 6774cd49는 미실행 상태 확인 후 종료하고 a22e7743-58e3-409b-acf1-0fb9f7d9fd24로 갱신했다. 새 계획 최초 만료는 15:51:53 KST이며, 만료 후 실행하려면 재조회·재생성이 필요하다. 아래 ‘준비한 계획’은 이전 준비 이력이다.

계정의 서울 고정 IP 한도는 5개 중 1개 사용으로 확인했다. 실제 쓰기 권한은 미검증이다. 미연결 IP 보관 비용과 근거는 점검 기록에 정리했다. 기존 IP·서비스 포트의 TCP 확인이 실패하면 신규 할당 전에 중단하는 사전 검사를 코드에 추가했다. 빌드·기본 38개 및 DB 통합 41개 통과, 기존 관리자 보존을 위한 1개 생략. 실행 중 백엔드는 기존 코드이며 실제 변경 비활성 상태다. 보완 코드는 다음 백엔드 재시작 시 적용된다.

실제 Lightsail 변경 어댑터를 전용 영속 작업·승인 API와 연결했다. 실제 변경을 실행한 것은 아니다. 읽기 전용 시작 도구는 IEUM_LIVE_ROTATION_ENABLED=false를 강제로 적용한다. 계획 저장은 읽기 전용 AWS 조회와 로컬 DB 기록만 수행한다.

승인된 ‘먼저 진행해줘’는 구현·모의 검증까지의 승인이다. 실제 IP 할당·연결·DNS 수정은 별도 실행 승인이 필요하다. 이번 작업 중 실제 시작 도구나 실제 계획 run API를 실행하지 않았다.

## 사용자 화면

고객관리 / 서버관리 두 탭 중 서버관리에서 운영 서버를 조회하고 대상을 선택한다. ‘실제 IP 변경 계획·승인’에서 조회 결과로 계획을 저장한다. 계정 끝 4자리·서울 리전·서버·기존 고정 IP 이름·도메인·A 레코드 ID·새 고정 IP 이름·서비스 확인 포트·보유 정책을 확인한다.

계획은 15분 동안 유효하며 새 IP 주소는 할당 전 미리 알 수 없다. 만료 계획은 실행 전 취소하고 새 조회 결과로 다시 만든다. 실행에는 서버 이름을 정확히 입력하고 접속 중단·다른 이용자 없음·기존 IP 보관·키 유지를 확인해야 한다. 화면 확인과 별개로 서버 측 실행 설정이 비활성이면 403으로 거부한다.

실행 전 planned 계획만 취소할 수 있다. running·needs_review를 취소로 닫아 후속 할당을 반복하지 않는다. 중단 상태 확인은 실행 잠금이 없는 running만 needs_review로 바꾸며 자동 재전송하지 않는다.

## 실행·동시 작업·저장

004_live_rotation_plans.sql로 live_rotation_jobs·live_rotation_events를 추가했다. 기존 mock 작업과 분리한다. 동일 대상·동일 DNS의 열린 작업을 고유 인덱스로 제한하고 계정+인스턴스 및 계정+도메인의 세션 자문 잠금을 함께 잡는다. 다른 서버라도 같은 DNS를 수정하는 작업은 겹칠 수 없다.

JSONB의 키 순서와 무관한 정규화 해시를 저장하며 승인 요청의 해시·revision·대상 이름·만료·미실행 상태를 확인한다. HTTP는 계획 자체를 클라이언트 입력으로 받지 않는다. 실제 조회 가능한 서버는 서버 측 등록 목록으로 제한한다.

최종 승인 확인을 기록한 뒤 각 단계의 intent를 커밋하고 효과를 호출한다. 단계는 IP 할당 → 기존 IP 분리 → 신규 IP 연결 → TCP 서비스 확인 → Lightsail DNS A 갱신 → 공개 DNS·TCP 확인이다. 호출 결과가 불명확하거나 체크포인트 저장에 실패하면 다음 단계·재시도·원복 없이 확인 대기로 멈춘다. 프로세스 중단 후에도 자동 재실행하지 않는다.

실행 직전 계정·실행 중 인스턴스·기존 IP·고정 IP 연결·DNS 레코드 ID·A 값·공개 NS를 다시 확인한다. 실행 중에는 AWS 작업 완료와 실제 리소스 연결을 확인한다. 기존 IP 반환 API나 Outline 키 변경 API는 호출하지 않는다. DNS 전파가 늦어지면 추가 IP를 할당하지 않고 확인 대기로 남긴다.

TCP 포트 확인은 Outline 인증·터널 데이터 전송 성공과 다르므로 최종 사용자 앱의 동일 키 재접속은 직접 확인해야 한다. 현재 서비스 포트 기본값은 이전 사용자 확인값인 40665이고, IEUM_OUTLINE_SERVICE_PORT로 명시할 수 있다. 서로 다른 서버의 실제 포트는 실행 계획에서 반드시 다시 확인한다.

## 활성화 방법과 승인 경계

도구 tools/start-admin-live.ps1는 -EnableLiveChanges를 명시하지 않으면 실행을 거부한다. 실제 운영 변경에 대한 사용자 최종 승인 후에만 사용할 예정이다. 이번에는 PowerShell 구문만 검사했고 실행하지 않았다. 기존 3000번 백엔드를 확인해 종료한 뒤 승인된 계정·프로필로 해당 도구를 실행하고, 새 계획을 검토해 사용자 화면에서 별도 확인해야 한다. 자동으로 계획을 실행하는 시작 스크립트는 없다.

필요한 AWS 쓰기 권한은 AllocateStaticIp·DetachStaticIp·AttachStaticIp·UpdateDomainEntry이며 GetOperation·GetStaticIp 등 조회도 필요하다. 현재 IAM 쓰기 권한·고정 IP 할당 한도·실행 시 비용은 아직 검증·확정하지 않았다. IAM 정책은 변경하지 않았다. 기존 IP 반환과 별도 정리는 이번 실행 범위에 포함하지 않는다.
