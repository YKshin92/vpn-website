# IP 교체 완료 후 기존 IP 자동 반환

2026-10-17 / 구현·모의 검증 완료 / 실제 변경 비활성

최신 보완: verify에서 최대 2분 동안 DNS·서비스 읽기 재확인을 수행하도록 구현했다. 성공하면 기존 반환 단계로 이어지고 시간 초과/치명 오류는 반환 없이 중단한다. 진행·최종 사유도 기록한다. [대기 검증 범위와 모의 결과](DNS전파_대기검증.md). 새 대기 기능의 실제 교체 시험은 아직 미실행이다.

후속 실제 시험 완료: 사용자 별도 실행 승인으로 3.34.11.44 → 52.79.185.31 교체·DNS 갱신·기존 IP 반환·기존 키 정상 연결을 확인했다. 공개 DNS 검증에서 한 번 멈춘 뒤 상태 대조와 같은 작업 속행이 필요했으며, 완전 무인 성공으로 간주하지 않는다. 새 반환 어댑터 자체의 실제 완료를 확인했다. [최종 시험 기록](실제IP변경_자동반환시험_2026-10-17.md). 실제 변경 게이트는 다시 false다. 아래 미실행 설명은 구현 당시 기록이다.

## 승인과 정책

사용자는 기존 IP 보관이 필요 없다고 설명했고, ‘새 IP·서비스·DNS 검증 후 기존 IP 자동 반환, 중간 실패 시 중단’의 구현·모의 테스트 제안에 ‘진행해줘’로 승인했다. 이번 승인은 실제 AWS 변경 시험 승인이 아니다.

새 계획의 기본 정책은 선택 옵션 없이 검증 후 반환이다. 기존 고객 키는 유지한다. 반환한 IP는 같은 주소로 다시 확보한다고 보장할 수 없다. 과거 보관 계획과 완료 이력은 수정하지 않는다.

## 실행 순서

1. 기존 서버·IP·DNS·서비스 사전 점검 후 새 IP 할당
2. 기존 IP 분리
3. 새 IP 연결
4. 새 IP 서비스 포트 확인
5. DNS A 갱신·적용 확인
6. 공개 DNS·서비스 최종 확인
7. 기존 IP 반환·반환 완료 확인

검증 완료 시점에도 작업 상태는 running이며, 반환 확인까지 끝나야 succeeded가 된다. 모의 전용 이전 도구는 기존 보관 정책의 여섯 단계를 유지하고 화면에도 이전 정책 도구라고 표시한다. 새로운 일곱 단계는 실제 실행 경로에 가짜 연산을 주입한 테스트로 검증했다.

## 반환 직전 조건과 실패 처리

모든 선행 단계가 순서대로 완료됐고 마지막 확인 IP·DNS가 새 IP와 일치해야 반환 단계로 들어간다. 기존 IP와 새 IP 이름은 다르고 할당 주소도 달라야 한다. 반환 단계 자체도 호출 전 intent를 DB에 저장한다.

실제 어댑터는 다음을 다시 조회·대조한다.

- 기대 AWS 계정 일치
- 대상 인스턴스 실행 중·새 고정 IP 연결·새 공인 IP 일치
- 새 고정 IP 이름·주소·연결 서버·isAttached=true 일치
- 기존 고정 IP 이름·주소 일치, attachedTo 없음·isAttached=false
- DNS 관리 NS와 유일한 비별칭 A가 새 주소와 일치
- 공개 DNS가 새 주소를 포함하고 기존 주소를 포함하지 않음
- 새 IP의 서비스 포트 연결 성공

이 조건을 통과한 뒤 ReleaseStaticIp를 한 번 호출한다. AWS 작업 완료 응답과 전체 고정 IP 목록에서 기존 이름/주소가 없음을 확인한다. 성공은 state.oldIpCleanup.status=released로 기록한다.

서비스·DNS 등 앞 단계에서 실패하면 반환 호출은 없다. 반환 호출 이후 응답이나 DB 기록이 불확실하면 이미 반환됐을 수도 있으므로 pending=release·needs_review로 남긴다. 실제 반환 여부를 추측해 보관/성공으로 표시하지 않으며 자동 재호출·자동 원복·추가 할당을 하지 않는다. running 중단 복구도 확인 대기로만 전환한다. 실패 후 새 계획·취소로 기존 진행 기록을 덮지 않는다.

TCP와 공개 DNS 검증은 관리자 환경의 시점 검사다. 모든 고객 DNS 캐시의 동시 만료나 중국 접속 가능성·Outline 인증을 보장하지 않는다.

## 저장 계획·승인 호환성

새 계획에는 policyVersion=2, retainOldIp=false, releaseOldIpAfterVerification=true, retainKeys=true를 저장하고 해시에 포함한다. 실행 요청은 ackReleaseOldIp=true를 요구한다. 예전 ackRetainOldIp로는 실행되지 않는다.

이전 보관 계획은 UI와 API 양쪽에서 실행을 거부한다. 미실행 planned라면 취소 후 새 계획을 준비해야 하며, running/needs_review는 임의 종료하거나 재생성하지 않는다. 기존 성공 이력의 정책과 추가 승인 반환 기록은 그대로 조회한다. 저장은 기존 JSONB·감사 테이블을 사용하므로 DB 마이그레이션은 없다.

새 IP 변경 계획의 포트도 상태 점검과 동일한 서버별 config.servicePort를 사용한다. 다중 서버는 각 항목에 포트를 명시하며, 미설정 포트로 추측해서 실행 계획을 만들지 않는다.

## 관리자와 실행 경계

IP 교체 창에 검증 후 자동 반환 안내·반환 확인 항목·마지막 반환 단계를 표시한다. 이전 보관 계획에는 취소 후 새 계획 필요 안내와 기존 정책을 표시한다. 반환 단계 불확실 시 실제 상태 대조를 안내한다.

실제 실행 게이트는 false다. 읽기 전용 시작 도구를 사용해 관리자만 재시작했다. 실제 실행을 활성화하거나 새 실제 계획을 실행하지 않았다. 향후 실행 계정에는 기존 변경 권한 외 ReleaseStaticIp와 완료 확인 조회 권한이 필요하며, 이번에 IAM을 수정하지 않았다.
