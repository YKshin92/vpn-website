# 선택 서버 상태 점검

2026-10-17 / 구현·실제 HTTP 검증 완료 / 읽기 전용

후속 통합: 새 IP 변경 계획의 서비스 포트도 이 문서의 서버별 config.servicePort로 통일했다. 기존 IP 처리는 선택형 보관이 아닌 검증 후 자동 반환 정책으로 구현·모의 검증했다. [최신 정책](IP교체_기존IP자동반환.md). 아래 ‘향후 통합’ 설명은 이 변경 이전 기록이다.

## 범위와 사용

서버관리의 자동 조회 오류 해결 후 사용자가 다음 작업 진행을 요청했다. 이전에 제안한 실제 상태 점검 범위를 설명하고 구현했다. 실제 IP·DNS·키 변경은 수행하지 않는다.

관리자 새로고침 → 서버관리 → 서버 상세 → ‘상태 점검’. 선택 서버의 AWS 실행 상태·현재 공인 IPv4·TCP 포트 연결·공개 DNS 주소 비교·관리 영역 NS 일치·점검 완료 시각·TCP 응답 시간을 각각 표시한다. 목록의 서비스 칸도 결과를 반영한다.

이 점검은 관리자 백엔드에서 서버의 TCP 포트에 연결하는 검사다. Outline 비밀번호 인증·VPN 터널 데이터 송수신·중국에서의 실제 접속 성공을 뜻하지 않는다. 포트 실패만으로 서버가 꺼졌거나 차단됐다고 단정하지 않는다. TCP 응답 시간은 이 연결 검사 시간이며 VPN 속도가 아니다.

## 설정

- 기본 단일 서버: IEUM_OUTLINE_SERVICE_PORT. 현재 읽기 전용 실행 도구는 54137을 전달한다.
- 여러 서버: IEUM_AWS_SERVER_TARGETS의 각 항목에 숫자 servicePort를 지정한다. 예: `[{"instance":"vpnServer001","domain":"ieumvpn.link","servicePort":54137}]`.
- 여러 서버 항목에서 포트를 생략하면 글로벌 포트를 임의로 재사용하지 않고 ‘포트 미설정’으로 표시한다. 유효 범위는 정수 1–65535다.
- 여기의 서버별 포트는 새 상태 점검에 사용한다. 기존 IP 변경 계획의 포트 선택 코드는 아직 글로벌 환경 값을 사용하므로 여러 서버의 IP 변경을 활성화하기 전 별도 통합이 필요하다. 이번에는 IP 변경 경로를 수정하지 않았다.

## API와 보호

GET `/api/admin/servers/:instance/health`. 기존 관리자 인증·로컬 Host/Origin 제한을 적용한다. 서버 측 등록 목록에서만 대상을 찾으며 브라우저가 보낸 IP·URL·포트로 임의 연결하지 않는다. AWS 계정 확인 후 조회된 실행 중 인스턴스의 공인 IPv4에만 연결한다. 사설/루프백/링크 로컬/메타데이터 주소·문서용 주소·멀티캐스트 등은 거부한다.

TCP 검사 시간 제한은 4초이며 요청 대상별 진행 중 요청을 합친다. 결과는 최대 10초 캐시한다. 캐시된 결과는 원래 점검 시각을 유지한다. 실패 원인은 시간 초과·연결 거부·네트워크 경로·점검 권한 등 일반화한 코드로 전달하며 원본 오류·비밀정보·스택은 노출하지 않는다. 익명 401, 미등록 대상 404, 잘못된 설정/조회 예외 503. 변경용 POST 경로는 없다.

상태 API는 새 AWS/DNS 조회를 수행한다. 화면에는 그 조회 결과를 반영하되 기존 화면보다 오래된 스냅샷으로 덮어쓰지 않는다. 점검 도중 다른 서버를 선택해도 응답은 원래 서버에만 연결한다. 로그아웃 이후 늦은 응답은 폐기한다.

화면에서 1분이 지난 결과 또는 현재 IP/실행 상태와 달라진 결과는 ‘재점검 필요’로 표시한다. 만료 여부는 서버관리 화면을 보는 동안 10초 간격으로 갱신하며 자동 네트워크 점검은 하지 않는다. 현재 점검 기록은 프로세스/브라우저 메모리이며 DB 이력이나 장애 알림·자동 IP 교체와 연결하지 않았다.
