# 키 작업 중단 기록 대조·관리자 확인 종료

2026-10-18 · 개발 설명서 v0.21 · 대조 기능 제공, 007 DB 적용 승인 대기

## 사용 경로

[키 관리 페이지](http://127.0.0.1:3000/admin/keys?server=vpnServer001) 하단 **키 관리 작업 이력**을 펼친다. 전체/확인 필요/완료/관리자 확인 종료 필터를 제공한다. 각 작업의 **현재 상태 대조**에서 작업 시각·키 ID·원래 상태/사유·저장된 요청값·현재 키 존재/이름/개별 한도를 비교한다. 완료 작업도 현재 상태를 읽어볼 수 있지만 종료 처리하지 않는다.

## 대조 결과의 의미

| 결과 | 의미 |
| --- | --- |
| 현재 상태가 요청 내용과 일치 | 현재 관측값의 일치이며 과거 요청 성공이나 전달 완료를 증명하지 않음 |
| 현재 상태가 요청 내용과 다름 | 이후 수정/삭제됐을 수도 있어 과거 요청 실패로 단정하지 않음 |
| 기존 기록에 요청값 없음 | 기존 006 이력에 이름/한도 요청 원문이 없어 복구할 수 없음. 추정하지 않음 |
| 전달 확인 불가 | 접속 키 보기 요청이 사용자에게 전달됐는지는 서버 상태만으로 증명할 수 없음 |
| 서버 식별자 다름 | 재설치 후 같은 키 ID가 다른 키일 수 있어 확인 종료를 막음 |

생성/이름 변경은 요청 이름, 한도 변경은 개별 한도(해제 포함), 삭제는 키 부재와 비교한다. 비밀 접속 키는 조회하지 않는다. 대조 API는 Outline에 GET 요청만 한다.

## 확인 종료 설계

메모 저장은 과거 실패를 succeeded로 덮어쓰지 않는다. 별도 `closed` 상태로 처리하고 기존 reason/finished_at을 보존하며 review에 원래 상태/사유·담당자·메모·대조값·대조/종료 시각을 남긴다. 관리자 확인 종료가 되면 이 작업 때문에 걸린 차단이 풀릴 수 있지만, 키 변경 스위치를 켜지는 않는다. 키 수정·자동 재실행·삭제·원복도 하지 않는다.

서버명·키 ID 재입력과 영향 확인, 10~1,000자 메모가 필요하다. 메모에 접속 키·관리 URL·인증서 JSON 등의 비밀 정보를 입력하지 않도록 안내하고 일반적인 접속 키/관리 URL 형식을 거부한다.

종료 직전에 다시 서버 상태를 읽는다. 대조 지문·기록 버전·상태가 달라졌거나 대조가 5분을 넘으면 거부한다. 프로세스 간 공유 잠금으로 키 변경 작업과 기록 종료가 겹치지 않게 한다. intent는 생성 후 최소 2분 동안 종료할 수 없고, 잠금을 가진 실행 작업이 있으면 시간과 관계없이 거부한다. 서버 세대가 달라진 이력은 이 화면에서 강제 해제하지 않는다.

현재 상태가 다르거나 기존 요청값이 없는 경우에도 충분한 대조·메모·확인 후 관리자 확인 종료를 할 수 있도록 구현했다. 이때도 결과를 성공으로 만들지 않는다. 서버 외부 Outline Manager의 변경과 DB 기록을 원자적으로 묶을 수는 없으므로 대조 시점의 관측이라는 한계가 있다.

## DB·실행 경계

`backend/migrations/007_outline_key_reviews.sql`을 작성했지만 **아직 적용하지 않았다**. 기존 006은 수정하지 않았다.

- requested: 앞으로 수행할 작업의 안전한 요청 이름/한도만 보존. 과거 요청의 해시에서 원문을 복원하지 않음.
- review: 담당자·메모·원래 상태·대조 증거 보존.
- revision/updated_at: 동시 변경 탐지.
- closed 상태와 JSON 구조 제약 추가. 기존 부분 고유 인덱스는 intent/needs_review만 차단하므로 closed는 차단을 해제한다.

기존 006 DB에서도 요청 조회·상태 대조가 동작한다. 새 컬럼 존재 여부를 확인하며, 없으면 새 저널 기록은 기존 형식으로 유지한다. 새 요청값 저장·실제 종료 SQL/제약 적용은 007 승인 후 검증 대상이다.

`IEUM_OUTLINE_REVIEWS_ENABLED`는 기본 false이며 기존 키 변경 플래그와 분리했다. 읽기 전용 시작 도구는 키 변경·IP 변경·기록 종료를 모두 비활성화한다. 007 미적용 또는 종료 스위치 비활성이면 버튼/서버 API 모두 기록 종료를 거부한다. 실제 기록 종료는 기능 구현 승인만으로 실행하지 않았다.

## 코드·API

- `backend/outline-review.ts`: 대조·종료 서비스/인증된 GET compare·POST close 경로.
- `backend/outline-worker-lock.ts`: 키 실행/비밀 보기/기록 종료 공용 세션 잠금. 짧은 저널 트랜잭션 잠금과 다른 네임스페이스를 사용한다. 예외 시 해제하고 해제 실패 연결은 폐기한다.
- `backend/outline-control.ts`: 안전한 현재 상태 조회, 006 호환 요청값 저장, 실행 작업 잠금.
- `dist/key-admin.html/js/css`: 이력 필터·대조 창·메모/대상 확인, 서버 전환/로그아웃 후 오래된 응답과 입력 정리.

API:

- GET `/api/admin/servers/:instance/outline/operations/:id/compare`
- POST `/api/admin/servers/:instance/outline/operations/:id/close`

## 검증

- TypeScript 빌드 통과.
- 단위/컨트롤러 99개 통과. 일치/불일치/요청값 없음/전달 불명, 오래된 대조·변경된 상태·서버 재설치·작업 중·버전 충돌·종료 중복·메모 비밀 형식 거부, 이력 필터·오래된 화면 응답 폐기 포함. 마지막 상태 한글화 후 화면 컨트롤러 재통과.
- PostgreSQL 통합 52개 중 51개 통과, 1개 기존 관리자 보존 생략. 인증·CSRF·확인 종료 로직은 가상 서버/저장소로 검증. 실제 로컬 DB에서는 두 연결의 작업 잠금 경쟁과 예외 후 해제를 검증했다. 새 DDL/실제 종료 SQL은 미적용이므로 아직 실제 DB에서 시험하지 않았다.
- 실제 읽기 HTTP: 기존 테스트 키 삭제 작업 `d263c33d-bcd0-409e-9de9-e41b7c9badde` 대조 200, 현재 키 부재 일치. 과거 succeeded/실패 사유/완료 시각은 전후 동일. 비로그인 401, 기록 종료 403, reviewReady=false·closureEnabled=false 확인.
- 007 컬럼 미적용 확인. 기존 서버 키 1개, 키 변경 false 유지. 실제 키·DNS/IP·운영 작업 이력 종료·DB 스키마·GitHub 변경 없음. 검사 임시 관리자 정리.
- 브라우저 클릭/시각 검증은 기존 접근 정책 제한으로 수행하지 않았다. 실제 GET 대조와 컨트롤러 검증을 구분한다.
