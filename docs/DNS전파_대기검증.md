# DNS 전파·서비스 대기 검증

2026-10-17 / 구현·모의 검증 완료 / 실제 IP 변경 비활성

## 승인과 범위

실제 IP 교체 시험에서 DNS 최종 확인 단계가 중단돼 운영자 확인 후 속행이 필요했다. 최대 2분 동안 DNS와 새 IP 서비스 연결을 읽기 전용으로 다시 확인하고, 성공 시 기존 IP 반환으로 이어가는 제안에 사용자가 ‘그렇게 진행해줘’로 승인했다. 이번 작업은 코드·모의 테스트·로컬 적용이며 실제 IP·DNS 수정이나 반환을 수행하지 않았다.

## 동작

IP 할당·연결·DNS 갱신은 각 한 번만 수행한다. verify 단계는 120초 예산 안에서 약 5초 간격으로 읽기 검증만 반복한다. 조회 자체의 소요 시간도 예산에 포함한다. 최대 25회이며 예산 종료 시 진행 중인 조회/소켓을 취소한다. DB 진행 저장의 응답 시간은 별도 제약을 받으므로 전체 HTTP 작업 완료를 정확히 120초 이내로 보장하는 것은 아니다.

각 확인은 다음 순서다.

1. 관리 DNS의 유일한 비별칭 A가 계획의 새 IP와 일치하는지 조회
2. 공개 NS가 승인된 관리 영역과 일치하는지 조회
3. 공개 A가 새 IP를 포함하고 기존 IP를 포함하지 않는지 확인
4. 새 IP의 서비스 포트 TCP 연결 확인

이전 IP 응답, 이전/신규 혼합 응답, 빈 A 응답, 분류된 일시 DNS 조회 오류나 TCP 연결 지연은 남은 시간 안에서 재확인한다. 관리 A 불일치·NS 변경·계획에 없는 주소·인증/권한 문제·점검 권한 문제·일반화되지 않은 오류는 즉시 중단한다. 원본 오류·토큰·경로·스택을 기록하지 않는다.

검증 성공이면 verify 완료를 기록한 뒤 기존 release 단계가 연결·DNS·TCP 조건을 다시 확인하고 기존 IP를 반환한다. 시간 초과나 오류는 needs_review·pending=verify로 남으며 반환하지 않는다. 실패한 작업을 자동 재실행하거나 중단된 작업을 자동 속행하지 않는다. 반환 호출의 불확실한 응답도 재전송하지 않는다.

이번 기능은 실행 중 verify 단계 내부에서 일시적인 읽기 결과를 재확인하는 것이다. 전체 작업 재실행·AWS 변경 API 재시도와 구분한다. 중국 접속·Outline 인증이나 모든 고객 DNS 캐시의 전파 완료를 보장하지 않는다.

## 기록과 화면

state.dnsVerification에 status(waiting/verified/timed_out/failed), attempt, elapsedMs, timeoutMs, reason, checkedAt을 저장한다. 확인 진행을 기존 작업 이벤트와 상태에 커밋한다. 이후 실패 체크포인트에서도 구조화된 최종 원인을 보존한다. 진행 저장이 실패하면 다음 읽기나 반환을 이어가지 않는다.

관리자 IP 교체 창은 기존 3초 상태 조회로 ‘전파 확인 중’, 확인 횟수·경과 시간·사유, ‘확인 시간 초과’를 표시한다. 인증/권한·DNS 변경 등 중단 원인도 일반화된 안내로 표시한다. 예전 작업에 이 필드가 없으면 기존 이력을 그대로 보여준다. DB JSONB·이벤트 테이블을 사용해 마이그레이션은 없다.

## 검증과 적용

- 빌드·기본 66개 통과. DNS 지연 후 성공·혼합 주소·예상 밖 주소·2분 시간 초과·일시 TCP 오류·즉시 중단 오류·남은 시간의 진행 중 조회 취소·진행 저장 실패 중단을 모의 시계/가짜 연산으로 검증했다.
- DB 통합 48개 중 47개 통과·기존 최초 관리자 보존 1개 생략. 지연 시 진행 이력 저장 후 한 번만 반환, 시간 초과 원인 보존·반환 없음·동일 작업 재실행 거부 확인. 실제 AWS 변경 API는 테스트에서 호출하지 않았다.
- UI 컨트롤러 7개 재확인, JS 문법, 실제 HTTP 관리자 200·익명 401·최대 2분 안내/진행 코드·enabled=false·기존 성공 이력 보존 확인. 임시 검사 관리자/세션 정리. 브라우저 시각 검사는 기존 접근 제한으로 미실행이다.
- 읽기 전용 관리자 재시작으로 새 코드 적용. 실제 대기 경로의 IP 교체 시험은 아직 하지 않았다. 이전 수동 속행 시험을 이 기능의 실제 무인 성공으로 간주하지 않는다.
