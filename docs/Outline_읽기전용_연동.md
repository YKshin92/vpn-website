# Outline 읽기 전용 관리 연동

작성일: 2026-10-17 · 개발 설명서 v0.17

## 구현 범위

관리자 → 서버관리 → 서버 상세 → **키** 탭에서 Outline 키 ID·이름·포트를 조회한다. 고객 매핑은 아직 미연동으로 표시하며 가상 고객에 실제 키를 자동 연결하지 않는다. 생성·삭제·이름 변경·기간 만료 회수는 구현하지 않았다. 실제 AWS IP·DNS 변경도 이번 범위가 아니다.

## 연결 정보 등록

1. [로컬 관리자](http://127.0.0.1:3000/admin)에 로그인한다.
2. 서버관리에서 대상 서버를 선택하고 **키 → Outline 관리 연결 설정**을 펼친다.
3. Lightsail의 대상 인스턴스 SSH 터미널에서 `sudo cat /opt/outline/access.txt`를 실행해 현재 `apiUrl`과 `certSha256`을 확인한다. 파일이 없으면 재설치 때 출력된 연결 정보나 Outline Manager 설정에서 현재 값을 확인한다. 값을 얻기 위해 재설치하지 않는다.
4. 두 값을 채팅·문서에 보내지 않고 관리자 입력란에 넣는다. apiUrl이 IP 주소라면 호스트만 해당 서버 등록 도메인(현재 ieumvpn.link)으로 바꾼다. HTTPS·관리 포트·비밀 경로는 그대로 유지한다. **고객 서비스 포트 54137은 관리 포트가 아니다.**
5. 연결 정보를 저장하면 키 목록을 조회한다. 저장 성공과 실제 연결 성공은 별개다. 실패하면 관리 포트·방화벽·현재 인증서 지문·AWS 로그인 상태를 확인한다. 기존 재설치 전 정보는 재사용하지 않는다.

## 저장 및 통신

- 자격증명은 서버 프로세스에서 Windows DPAPI 현재 사용자 암호화로 저장한다. 기본 위치는 `%LOCALAPPDATA%\IeumVPN\outline-local\<서버>.dpapi`다. 브라우저 저장소·DB·저장소·명령행 인수에는 넣지 않는다.
- Windows 사용자 권한으로 복호화 가능하므로 OS 계정 접근을 보호해야 한다. 암호화 파일을 복사하는 것만으로 Linux나 다른 Windows 계정에 이관되지 않는다. 서버 이관 시 서버 측 비밀 저장소에 다시 등록한다. DB 이전은 기존 절차를 따르며 이번 DB 스키마 변경은 없다.
- 등록 서버만 조회하며 AWS 계정·인스턴스 조회에서 확인한 실행 중 공개 IP로 연결한다. 사용자 입력 URL의 임의 호스트나 사설 IP로 접속하지 않는다.
- 자체 서명 인증서를 SHA-256으로 고정 검증하고 일치한 후에만 비밀 HTTP 경로를 전송한다. 전역 TLS 검증을 끄지 않으며 리다이렉트를 따르지 않는다.
- Outline 원본 응답의 password·accessUrl 등은 버리고 ID·이름·포트만 반환한다. 전체 키·관리 주소·지문은 조회 응답이나 오류 메시지에 포함하지 않는다.
- 로그인·동일 출처·CSRF 제한을 적용한다. 서버별 10초 캐시와 중복 조회 병합, 조회 대상 전환 및 로그아웃 후 이전 응답 폐기를 적용한다.
- 연결 정보 저장은 로컬 설정 쓰기다. VPN 서버 키는 변경하지 않는다.

## API

| 경로 | 동작 |
| --- | --- |
| GET /api/admin/servers/:instance/outline/connection | 등록 여부·갱신 시각만 반환 |
| POST /api/admin/servers/:instance/outline/connection | 관리 연결 정보를 로컬 암호화 저장 |
| GET /api/admin/servers/:instance/outline/keys | 키 ID·이름·포트 조회 |

## 검증과 남은 작업

- TypeScript 빌드 통과.
- 단위·컨트롤러 테스트 73개 통과. 인증서 불일치 시 HTTP 요청 0건, 리다이렉트 차단, 비밀 필드 제거, 등록 대상 제한, 사설 IP 차단, 캐시 무효화, 서버 전환·로그아웃 응답 폐기, 가상 자격증명 DPAPI 저장·복호화 확인.
- PostgreSQL 통합 테스트 49개 중 48개 통과·1개 기존 관리자 보존 사유로 생략. 관리자 인증·CSRF·비밀 값 응답 제외·키 쓰기 경로 부재 포함. 테스트 임시 관리자는 정리한다.
- PowerShell 7에서 상속된 모듈 경로 때문에 Windows PowerShell 암호화 모듈 로딩이 실패하는 문제를 발견하고 자식 프로세스의 시스템 모듈 경로를 지정해 해결했다.
- HTTPS·DPAPI 테스트는 sandbox 밖에서 가상 데이터로 검증했다. 테스트 PEM 개인 키는 로컬 가상 HTTPS 전용이며 실제 서비스에 사용하지 않는다.
- 브라우저 접근 정책 제한으로 클릭·시각 검증은 수행하지 않았다. 소스·컨트롤러 및 HTTP 검증과 구분한다.
- 로컬 관리자 백엔드를 읽기 전용 모드로 재시작하고 HTTP로 화면 제공·미인증 401·configured=false·not-configured/count=null을 확인했다. 실제 IP 변경 enabled=false도 확인했다.
- **현재 서버의 재설치 후 관리 자격증명 입력 및 실제 키 조회는 대기**다. 저장 후 실제 조회 결과를 확인해야 한다.
- 다음 단계는 실제 키 ID와 고객 DB의 명시적 1:1 연결 설계다. 자동 추정 연결이나 기존 키 교체 없이 별도 승인 후 진행한다.

공식 근거: [Outline Server 관리 API 안내](https://github.com/OutlineFoundation/outline-server/blob/master/src/shadowbox/README.md), [OpenAPI 명세](https://github.com/OutlineFoundation/outline-server/blob/master/src/shadowbox/server/api.yml).

## 2026-10-17 — 저장 결과 표시 보완

사용자가 저장 후 입력값이 사라지고 변화가 보이지 않는다고 보고했다. 진단 시 로컬 API는 configured=false·not-configured를 반환했으며 기본 암호화 저장 디렉터리에 등록 파일이 없었다. 이전 저장 시도의 정확한 실패 이유는 기록이 없어 확정하지 않았다.

- 성공 시 입력값을 비우는 기존 보안 동작은 유지하고, 저장 중·실패·등록됨 상태를 입력란 바로 아래에 표시한다.
- 저장에 실패하면 입력값을 유지하며 주소 형식·인증서 형식·암호화 저장 오류를 구분해 안내한다. 오류 내용에 입력값을 포함하지 않는다.
- 키 탭을 열 때 비밀 값이 없는 connection 메타데이터를 먼저 조회해 등록 여부·갱신 시각을 보여준다. 등록 성공과 실제 API 연결·키 조회 성공을 분리한다.
- 컨트롤러 테스트 11개 통과. 추가한 3개는 저장 실패 시 입력 유지, 성공 시 비밀 입력 비우기·등록 표시, 저장됐으나 인증서 불일치로 키 조회 실패하는 경우를 검증한다.
- HTML·JS는 로컬 백엔드가 파일에서 제공하므로 페이지 새로고침으로 반영된다. 실제 AWS·Outline 키·DB 스키마·GitHub 변경 없음. 브라우저 클릭 검증은 미실행이다.
- 다음 확인: 사용자 새로고침 후 재저장, 표시되는 실패 사유를 기반으로 현재 연결 정보 또는 로컬 저장 환경을 확인한다. 비밀 값은 채팅에 보내지 않는다.
