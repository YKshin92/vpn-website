## 구현 범위와 한계

Node.js·TypeScript·Fastify API를 PostgreSQL 개발 DB에 연결했다. 가상 고객·서버·개별 키 저장·조회 기능이다. 실제 AWS·DNS·Outline·결제 호출은 없다. 인증 전 개발 API이므로 127.0.0.1에서만 실행하고 가상 데이터만 사용한다.

홈페이지는 아직 이 API에 연결하지 않았다. 기존 관리자 데모·내 이용권은 브라우저 메모리와 기존 가상 데이터를 사용하며 IP 변경 화면도 이전 원복 방식을 유지한다. 만료·주문·결제·이용권 이력 테이블은 이번 범위에 포함하지 않았다.

설치: Fastify 5.12.7, pg 8.23.1, TypeScript 7.0.2. Node 타입 정의는 런타임과 동일한 24 메이저로 고정했다. 정확한 버전은 잠금 파일을 따른다. 설치 시 npm 감사 결과 알려진 취약점 0개였으며 전체 보안 감사 완료를 의미하지 않는다.

공식 참고: [Fastify 서버](https://fastify.dev/docs/latest/Reference/Server/), [매개변수 쿼리](https://node-postgres.com/features/queries), [트랜잭션](https://node-postgres.com/features/transactions).

## 데이터와 권한

개발 DB ieum_vpn_dev에 ieum_dev.servers·customers·access_keys를 생성했다. 초기 데이터는 fixtures/demo의 서버 1개·고객 5명·개별 키 5개다. 고객 상태는 예시이며 실제 결제나 만료 판정 결과가 아니다.

- 서버는 서울 리전·simulation 모드·.test 호스트로 제한한다.
- 이메일은 소문자 .test 주소로 저장하며 고유 제약을 적용한다.
- 키는 고객·서버 외래키, 고객별 키 하나, 같은 서버의 Outline 키 ID 고유 제약을 적용한다.
- 키 비밀번호·접속 키 원문·관리 API URL은 저장하거나 제공하지 않는다.
- 앱은 세 업무 테이블의 SELECT·INSERT·UPDATE·DELETE만 갖고 DDL 권한이 없다. DELETE는 통합 테스트 데이터 정리에 사용하며 삭제 API는 제공하지 않는다.
- 스키마 변경은 관리 자격증명으로 실행한다. public.ieum_schema_migrations의 적용 이력에는 앱 쓰기 권한을 주지 않는다.

마이그레이션은 트랜잭션과 DB 자문 잠금으로 직렬화한다. 적용 파일 내용이 달라지면 중단하고 동일 파일 재실행은 건너뛴다. 체크섬은 CRLF·LF 차이를 정규화한다. 기존 파일 수정 대신 새 번호 SQL을 추가한다.

seed는 트랜잭션으로 입력하며 같은 ID는 덮어쓰지 않는다. 기존 수정 내용을 초기화하는 명령이 아니다. 재실행 후 기본 데이터 개수 유지와 임시 테스트 데이터 정리를 확인했다.

마이그레이션 전 PowerShell 실행 도구가 보호된 자격증명 폴더의 backups 하위에 pg_dump 백업을 생성한다. 백업 실패 시 적용하지 않는다. 복원은 아직 미검증이며 작업 4의 별도 승인 대상이다. npm의 db:migrate 명령을 직접 실행하면 이 백업 단계는 생략되므로 로컬에서는 아래 도구를 사용한다.

## API와 실행

현재 로컬 미리보기: http://127.0.0.1:3000/api/health

| 경로 | 동작 |
| --- | --- |
| GET /api/health | 실제 DB 연결 및 local-synthetic·authenticated:false 표시 |
| GET /api/dev/customers | 고객·키 ID·서버 ID, 최대 200개 |
| POST /api/dev/customers | displayName·email·status로 가상 고객 생성 |
| GET /api/dev/servers | 서버 조회, 최대 100개 |
| POST /api/dev/servers | name·hostname으로 서울 가상 서버 생성 |
| GET /api/dev/keys | 고객·서버·키 ID 매핑, 최대 200개 |
| POST /api/dev/keys | customerId·serverId·outlineKeyId로 가상 키 할당 |

신규 키 ID는 demo- 접두사만 허용한다. 추가 JSON 필드·실제 호스트·실제 이메일·외부 Host/Origin·cross-site 요청을 거부한다. 중복은 409, 입력·외래키 오류는 400, 내부 DB 오류는 상세 없이 503으로 응답한다. CORS를 열지 않았으며 이 제한은 관리자 인증을 대신하지 않는다. 기존 홈페이지 4173에서 API 3000으로 호출하도록 연결하지 않았다.

프로젝트 폴더에서 다음처럼 실행한다. PC나 도구 세션 종료 후에는 다시 실행해야 한다.

```powershell
npm.cmd run build
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/backend.ps1 -Task start
```

DB·가상 데이터 변경 명령은 승인받은 작업 범위에서만 사용한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/backend.ps1 -Task migrate
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/backend.ps1 -Task seed
```

비밀번호는 Windows 보호 로컬 파일에서 실행 프로세스 환경에만 넣으며 종료 시 기존 환경을 복구한다. migrate는 관리 계정, seed·start·test는 앱 계정이다. Windows 암호화 파일을 서버에 복사하지 않고 서버 환경변수·비밀 저장소를 별도로 설정한다. 현재 코드는 ieum_vpn_dev만 허용하므로 운영 설정 지원은 후속 작업이다. SQL 원본 파일도 필요하므로 .build 폴더만으로 배포하지 않는다.

## 검증 결과

- TypeScript 빌드 통과, 마이그레이션·seed 재실행 시 중복 생성 없음.
- 기존 가상 기능 20개 테스트 통과.
- 새 통합 테스트는 상위 1개·하위 9개로 Node 집계 10개 모두 통과.
- 가상 서버·고객·키 등록·조회와 잘못된 입력·외부 요청 차단 확인.
- 동시 동일 키 할당은 201 한 건·409 한 건, 고객별 추가 키 할당 거부 확인.
- SQL처럼 보이는 이름이 쿼리 실행 없이 값으로 저장됨을 확인.
- 앱 계정 CREATE TABLE 거부 확인.
- 별도 Node 프로세스 두 차례 실행에서 새로 저장한 고객 조회 확인.
- 실제 HTTP 프로세스 두 차례 시작·종료 후 health·가상 데이터 개수·로컬 바인딩 확인.
- 테스트 생성 데이터 제거 후 서버 1개·고객 5명·키 5개 유지.

테스트 명령:

```powershell
npm.cmd test
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/backend.ps1 -Task test
```

HTTP 재실행 검사는 3000 포트가 비어 있을 때 tools/test-backend-http.ps1로 실행한다. 자신이 시작한 프로세스만 종료하며 기존 서비스는 중지하지 않는다.
